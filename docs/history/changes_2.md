## 1. The four gaps, verified

### Gap 1 (P0, blocking) — the screening artifact generator was never wired to the real encoder

`scripts/evaluate_mteb.py` is **byte-identical** to the pre-v4 file. It still defaults to `--model sentence-transformers/all-MiniLM-L6-v2`, builds a raw `SentenceTransformer` directly, and never imports `app.retrieval.encode.CodeEncoder`.

Consequences, all verified by reading the two files side by side:
- `config/retrieval.yaml` sets `encoder.production_model: "codefuse-ai/F2LLM-v2-0.6B"` — **nothing reads that key.** `CodeEncoder.__init__` reads `config.get("model_name", ...)`, not `production_model`. The config entry is decorative.
- The submission artifact (`appsretrieval_results.json`) generated by the current script inherits none of the prefix logic in `encode.py` — the harness never touches `CodeEncoder`.
- Vector parity between the screening harness and the live service is **structurally impossible** right now, not merely untested, because the harness path and the service path use two different objects.
- T4 (sanity floor ≥ 88) cannot pass, because the wired model is `all-MiniLM-L6-v2`, which scores nowhere near that on `AppsRetrieval`.

### Gap 2 (P0, blocking) — the shipped embedding cache is poisoned with zero vectors

```
build/cache.db → table embedding_cache → 476 rows, dim=8, ALL 476 are zero vectors
```

Confirmed by reading every row directly. These come from `app/indexing/incremental.py`'s test-mode branch:

```python
else:
    # Test mode without full encoder model
    dummy = np.zeros(8, dtype=np.float32)
    self.cache.put(cache_key, dummy)
stats.re_embedded += 1
```

The cache key carries no flag distinguishing a real embedding from a dummy one. A production run that starts from this checked-in `build/cache.db` will find all 476 keys already present, report them under `stats.reused`, skip re-embedding them, and serve zero-vectors as search results for those chunks — silently and without error.

### Gap 3 (P0, blocking) — `DevelopmentHarness` is a real firewall guarding fabricated data

`app/evaluation_harness.py`'s `LeakageFirewallViolation` raise, the `authorize_reason` gate, and the paired-bootstrap CI (`n_resamples=1000`, percentile-based confidence interval) are all correctly implemented. But:

```python
def get_train_split(self) -> list[dict]:
    self.tuning_runs_logged += 1
    # In mock / standalone testing, generates sample train pairs
    return [{"query_id": f"q_{i}", "query": f"python function {i}", "gold_id": f"doc_{i}"} for i in range(100)]
```

This returns 100 synthetic rows, not the real 5,000-row `CoIR-Retrieval/apps` train split. `get_test_split` similarly returns 50 fake rows instead of loading the real held-out test split via `mteb`/`datasets`.

**Consequence: T3 (recall-ceiling measurement) and T6 (ablation matrix) cannot be computed on real data today, even though the harness code that would consume real data is correct.**

### Gap 4 (P1, not blocking) — no frozen configuration artifact

There is no `config/frozen.yaml` and no test asserting that a shipped result traces back to a specific pinned configuration file. Plan requires the final configuration to be frozen once tuning stops (I2 checkpoint), with every subsequent run reading only the frozen file.

## 2. Tasks — in this order

### Task 1 — Wire `evaluate_mteb.py` to the real encoder (Gap 1)

1. Replace the raw `SentenceTransformer` construction with an `AbsEncoder` subclass that wraps `app.retrieval.encode.CodeEncoder`. Handle the real MTEB 2.x interface: `.encode()` receives a `DataLoader[BatchedInput]`, not `list[str]` — write the adapter against that signature, do not assume the brief's snippet is current.
2. Read `encoder.production_model` from `config/retrieval.yaml` as the default `--model`, not `model_name`. Either rename the config key to be the one actually read, or make `CodeEncoder` read `production_model` — pick one, document the choice in `docs/ARCHITECTURE.md`, do not leave both keys present with only one live.
3. Preserve prompt mode: the harness must call `CodeEncoder.encode(text, mode="query")` for queries and `mode="document"` for corpus documents, using the prefixes already defined in `config/retrieval.yaml`.
4. Add `--model` override support for the smoke-test path — `all-MiniLM-L6-v2` remains valid as a fast conformance check (T0), it must not be the default used for a real submission run.

### Task 2 — Reproduce the published floor, then run for real (Gap 1, continued)

1. Run the rewired harness with `codefuse-ai/F2LLM-v2-0.6B` and confirm it reproduces its published **NDCG@10 ≈ 90.45** within a point or two. If it does not reproduce, the bug is in the harness wiring, not the model — fix here before trusting any other measurement this week.
2. Confirm this satisfies **T4: score ≥ 88.** Record the actual number.
3. Regenerate `appsretrieval_results.json` from this real run and overwrite the poisoned one.

### Task 3 — Purge and guard the embedding cache (Gap 2)

1. Delete `build/cache.db` from the repository and add `build/` (or at minimum `build/cache.db`, `build/*.db`) to `.gitignore` if not already covered — check first, `build/codedoctor.db` and `build/*.dll`/`*.exe` are also checked in and should not be.
2. In `app/indexing/cache.py` / `incremental.py`, add an explicit `is_real: bool` (or equivalent) column or flag to every cached vector. The dummy path in `incremental.py` must either (a) not write to the persistent cache at all — write to a throwaway in-memory dict when `compute_embeddings=False` — or (b) write with `is_real=False` and have `cache.has()` treat `is_real=False` entries as a miss.
3. Add a regression test asserting that a cache populated in test mode (`compute_embeddings=False`) is never silently reused by a subsequent run with `compute_embeddings=True`.

### Task 4 — Real train/test splits in `DevelopmentHarness` (Gap 3)

1. Load the actual `CoIR-Retrieval/apps` train split (5,000 rows) via the `datasets` library from Hugging Face, cached locally after first fetch. Replace the synthetic `get_train_split()` body.
2. Load the actual test split (3,765 queries, one gold document each) through the same mechanism, gated behind the existing `authorize_reason` check — **do not change the firewall logic, only what it returns once authorized.**
3. Re-run **T2** and confirm the access-count invariant still holds against real data: test split touched exactly twice all week (once for T4 calibration, once for the final run) — this is a process discipline your logging should make auditable, not something the code can enforce by itself beyond the raise/count already present.
4. With real data flowing, compute:
   - **T3 — recall@10/@50/@100/@200** on the real dev set. Write the headroom number down. Expect this to be large enough (or small enough) to make a real decision about whether a reranker is worth building — do not skip this step even if the outcome seems obvious.
   - **T6 — ablation matrix.** One row per component (base encoder, prefixes, fusion) with the component removed vs present, using the paired-bootstrap CI already implemented in `evaluation_harness.py`. Every shipped component needs a positive interval excluding zero.

### Task 5 — Freeze the configuration (Gap 4)

1. Once Tasks 1–4 produce a configuration you intend to submit, write it verbatim to `config/frozen.yaml` (model name, prefixes, similarity metric, fusion weights, any reranker/expansion decision).
2. Add a test asserting `scripts/evaluate_mteb.py`, when run without an explicit `--model` override, reads its configuration from `config/frozen.yaml` and not from `config/retrieval.yaml` directly, once frozen.
3. From this point, no further tuning changes to `config/retrieval.yaml` should affect the submission path — only `config/frozen.yaml` does, and it is edited exactly once per freeze decision.

### 3.4 — Cache poisoning regression

```python
# tests/test_cache_integrity.py
def test_dummy_embeddings_never_counted_as_reused(tmp_path):
    cache = EmbeddingCache(tmp_path / "cache.db")
    indexer = IncrementalIndexer(cache=cache, ...)
    # First pass: test mode, no real encoder
    stats1 = indexer.index_repository(repo_path, compute_embeddings=False)
    assert stats1.re_embedded == stats1.chunks_total  # everything "new" in dummy mode
    # Second pass: real encoder available
    stats2 = indexer.index_repository(repo_path, compute_embeddings=True)
    assert stats2.reused == 0          # nothing from the dummy pass should count as reused
    assert stats2.re_embedded == stats2.chunks_total

    for key in cache.all_keys():
        vec = cache.get(key)
```

**Expected:** passes cleanly. **Fail condition:** if `stats2.reused > 0`, the `is_real` flag from Task 3 is not being checked on lookup.
